Positional links between network items

Tie a sticky note, a network box, a dot or a node to another item so it follows when that item moves, the way a background image can already be pinned to a node. Here is what Houdini offers, the options for building it, and a working prototype.

Checked against Houdini 21.0.729 and 22.0.429 sources · prototype package tethers

The model: leaders and followers

Each follower has one leader. Dragging the leader carries its followers, recursively. Dragging a follower on its own only changes its offset. Chains are allowed; cycles are refused.

The arrow points from leader to follower. A round anchor marks the leader end, a filled head marks the follower.

What Houdini already has

Linked images
hou.NetworkImage.setRelativeToPath() ties a background image to a node, box or sticky note. The editor stores it in the network's user data under backgroundimages, so it saves with the hip. Nothing equivalent exists for other items.
Network boxes
The only native grouping. Moving the box moves its contents, but you can't make an item follow without putting it in a box.
Move events
hou.nodeEventType.PositionChanged fires for nodes only. StickyNoteChanged fires on text edits and NetworkBoxChanged on membership changes. Neither fires on a move.
How a drag works
nodegraph.MovableItemMoveHandler.getItemsToMove() decides what moves. During the drag, positions are only previewed with editor.setAdjustments(). On release, applyAdjustments() calls setPosition once per item inside one Move items undo group. Same code in H21 and H22.
Drawing
After every editor event, nodegraphutils.EditorUpdates.applyToEditor() replaces the editor's shapes. Anything drawn once with setShapes disappears on the next mouse move.
Menus
A NetworkViewMenu.xml on the Houdini path supplements the network editor's menu bar, so a package can add its own menu and extend View. Nodes also get OPmenu.xml. The sticky-note and network-box right-click menus are hard-coded Python and can't be extended.
Toolbar
The icon buttons at the right of the network editor's menu bar aren't Qt. They come from config/Applications/FUSE_NetEditorApp.ui, a compiled Houdini UI-script file. H21 ships its text source in config/OldUIFiles.cpio.gz, and a copy earlier on HOUDINI_PATH replaces it. Each button is ACTION_ICONBUTTON "icon" SENDSKEY("h.pane.wsheet.…"), so it can trigger the package's own menu actions.
Storage
Sticky notes and network boxes have no user data. Links live on the parent network instead, as linked images do.

Three ways to make followers move

ApproachFeelLeader typesUndoVerdict
Node event callbacks (PositionChanged)Followers jump into place on release, not during the dragNodes onlyExtra steps unless handledfallback
Wrap the drag handler (getItemsToMove)Live: followers preview, snap and drop with the dragNode, sticky, box, dotOne step, shared with the dragchosen
Polling (hou.ui.addEventLoopCallback)LaggyAllMessyavoid

The prototype combines the first two. The drag wrapper handles every interactive move. For moves that aren't drags (layout, align, scripts), a PositionChanged callback on node leaders re-places followers at their stored offset. It runs with undo disabled, so undoing the leader's move re-places the followers through the same callback. Sticky and box leaders have no such fallback, because Houdini sends no event when they move.

UX

Creating a link

Tether to Leader, Unlink and Select Tethered are icon buttons at the left of the network editor's own toolbar icons. They send the actions of a Links menu (after Layout), which also holds the three display modes. The buttons only work through menu-defined actions, so the menu has to stay. Its h.pane.wsheet.tethers_* ids can also take network-editor hotkeys in the Hotkey Manager. A Links radial menu holds the same actions plus the display modes, and nodes get Link and Unlink in their right-click menu.

Select the followers, click the Tether to Leader button, then click the leader. While you pick, a dashed arrow runs from the cursor to each pending follower, and turns solid when it snaps to an item. Esc or a click on empty space cancels. This mirrors how a linked image is pinned, and avoids guessing the leader from selection order.

Seeing links

Links are drawn in the network editor as smooth, antialiased arrows in orange: a round anchor at the leader, a filled head at the follower. Only the arrows are drawn, with no boxes around items. They sit under the items, track the drag preview live, and keep a constant on-screen size at any zoom. Three modes, remembered across sessions, are set from the Tethers menu, the radial menu, or a Positional Links section in the View menu, right under Dependency Links and worded the same way:

  • Hide.
  • Show for Selected Items (default): only the chains touching the selection.
  • Show for All Items: every link in the current network.

A Python panel listing leaders and followers (click to select or frame) is a possible v2. The in-graph display already answers “what is linked to this?”.

Breaking a link

Unlink removes the selected items' links, both as followers and as leaders. Select Tethered grows the selection to the whole chain, which is handy before deleting or moving a group. Deleting an item drops its links automatically.

Behaviour, tested in H21.0.729

  • passMouse drag of a node leader: sticky, box (with its contents), dot and chained followers all move by the same delta, live.
  • passOne undo restores the leader and every follower.
  • passDragging a follower alone leaves its leader in place and stores the new offset.
  • passAlt-drag copy duplicates only the grabbed items, not their followers.
  • passScripted setPosition on a node leader moves its chain (fallback path).
  • passCycles refused; renaming a node keeps its links; deleting an item drops its links.
  • passLinks save with the hip; callbacks re-register on load and merge.
  • passClick-to-pick leader from Tether to Leader, with the live arrow preview.
  • untestedLayout (L), align, drop-on-wire with followers in the drag, and very large networks.

Known limits

  • Copy/paste drops links, because pasted items get new names.
  • Dropping a leader into a network box also pulls its followers into that box.
  • Links only work within one network level.
  • Sticky and box leaders only carry followers during interactive drags; scripted moves of them aren't caught.
  • The package wraps three functions of SideFX's nodegraph Python. A future Houdini may change them, so re-check on each major version.
  • The toolbar override is a full copy of SideFX's FUSE_NetEditorApp.ui for build 21.0.729. Re-derive it from each new build's OldUIFiles.cpio.gz, or a stale copy may hide new toolbar features.
  • Without the package, links stay in the hip as inert data and change nothing.

Try it

The package sits in the session folder as tethers/:

tethers/
  tethers.json            package: adds this folder to HOUDINI_PATH
  NetworkViewMenu.xml     Links menu + View › Positional Links
  OPmenu.xml              node right-click: Tether to Leader…, Unlink
  config/Applications/
    FUSE_NetEditorApp.ui  network editor toolbar + 3 link buttons
  radialmenu/
    tethers.radialmenu    Links radial menu (bind a hotkey)
  python3.11libs/
    uiready.py            installs the editor hooks at startup
    tetherspick.py        click-the-leader editor mode
    tethers/core.py       link storage, chains, callbacks
    tethers/editor.py     drag wrapper, arrow drawing, display modes
    tethers/tools.py      menu entry points

Launch Houdini 21 with HOUDINI_PACKAGE_DIR pointing at the tethers folder. To install it permanently, copy tethers.json into houdini21.0/packages and set its "path" to the folder's location. Menu changes need a Houdini restart.
